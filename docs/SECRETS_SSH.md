# Как передать секреты и data.zip

Да, SSH подходит. Для файла удобнее SFTP (например, WinSCP в режиме SFTP) или `scp`: они передают данные через защищённое SSH-соединение. Это защищает передачу, но не скрывает файл от администраторов целевого сервера.

## Порядок действий

1. IT сообщает адрес, порт, именную учётную запись, способ входа и отпечаток SSH-ключа сервера. Сверить отпечаток по отдельному доверенному каналу при первом подключении. При неожиданной смене ключа остановиться и выяснить причину. Не отключать проверку ключа.
2. В домашней папке администратора создать закрытую папку для передачи. Команды ниже используют пример `ituser@server`; его нужно заменить. Если порт нестандартный, у `ssh` используется `-p`, у `scp` — `-P`.

```bash
ssh ituser@server 'umask 077; mkdir -p ~/radar-transfer; chmod 700 ~/radar-transfer'
scp .env ituser@server:radar-transfer/radar.env
scp data.zip ituser@server:radar-transfer/data.zip
```

3. IT устанавливает секреты на сервере, не выводя их содержимое в терминал:

```bash
chmod 600 ~/radar-transfer/radar.env
sudo install -o root -g radar -m 0640 ~/radar-transfer/radar.env /etc/radar/radar.env
rm ~/radar-transfer/radar.env
```

4. Перенести данные по основной инструкции. После проверки удалить временные копии с сервера; исходную контрольную копию оставить в согласованном защищённом месте. Простое удаление файла не гарантирует его физического стирания из снимков и резервных копий.
5. После изменения секретов перезапустить службу. При смене `BRIDGE_TOKEN` обновить и `RADAR_TOKEN` в Colab.

В команды не вставлять значения токенов и паролей: они могут сохраниться в истории shell. Не отправлять заполненный `.env`, архив данных и приватные SSH-ключи в общий чат или репозиторий. Передаются настройки бота; личный приватный SSH-ключ сотрудника передавать коллегам не нужно.

Исходный ZIP проекта содержал заполненный `.env`. В подготовленную поставку он не включён. Если исходный ZIP уже попадал к лишним получателям или в доступное другим хранилище, перевыпустить соответствующие ключи и пароли. Удаление `.env` из нового архива не отзывает старые копии.

В `data/` могут находиться ключи прежнего туннеля, URL с токенами, отчёты и служебные данные. Архивировать папку целиком для сохранения состояния, а решение об использовании или отзыве старых ключей принять отдельно после переноса. При ненужном встроенном туннеле оставить `TUNNEL` пустым.

Документация OpenSSH: https://man.openbsd.org/scp и https://man.openbsd.org/ssh.
